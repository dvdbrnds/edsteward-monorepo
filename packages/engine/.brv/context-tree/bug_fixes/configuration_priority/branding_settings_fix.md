Fixed critical branding configuration save issue in EdSteward. Problem: Branding colors and settings were not saving/persisting despite successful API calls. Root cause: In server/storage.ts getBrandingConfig() method, environment variables (from .env file) had higher priority than database configuration, so saved settings were ignored. Environment variables like INSTITUTION_NAME=Moravian_University were overriding database saves. Solution: Modified priority order in getBrandingConfig() to check database FIRST (Priority 2), then fall back to environment variables (Priority 3) only if no database config exists. This allows branding settings to be saved and persist correctly while still supporting environment-based configuration as fallback. Tested successfully: branding configuration now saves and persists across server restarts. Both /api/admin/branding and /api/branding endpoints return saved configuration. This was a recurring issue mentioned in git commits.
